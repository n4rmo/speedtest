# speedtest

Консольный скрипт на Python, который измеряет скорость скачивания: делает 10 последовательных HTTP(S)-запросов к одному адресу, каждый раз дожидается полного ответа и печатает среднее время запроса, общий объём и скорость.

## Требования

- Python 3.9 или новее (проверено на 3.13)
- Только стандартная библиотека, ничего устанавливать не нужно

## Запуск

```bash
python speedtest.py <URL>
```

Пример со «тяжёлой» картинкой:

```bash
python speedtest.py https://example.com/big-image.jpg
```

Справка: `python speedtest.py -h`

## Что считается и в каких единицах

| Величина | Единицы |
| --- | --- |
| Время запроса | секунды (с) |
| Объём данных | байты и мегабайты (1 MB = 1 000 000 байт) |
| **Скорость скачивания** | **мегабиты в секунду (Мбит/с)**, 1 Мбит = 1 000 000 бит |

Формула: `скорость = (общий объём в байтах × 8) / суммарное время всех запросов / 1 000 000`.
Это общая скорость по всем запросам, а не среднее арифметическое скоростей отдельных запросов.

## Пример вывода

Запуск на локальном сервере с файлом 20 МБ (на реальном интернете цифры будут другими):

```
Запрос 1/10: 20000000 байт за 0.053 с
...
Запрос 10/10: 20000000 байт за 0.011 с

Среднее время запроса: 0.018 с
Скачано всего: 200000000 байт (200.000 MB)
Скорость скачивания: 9051.129 Мбит/с
```

## Как это устроено

- Файл читается кусками по 64 КБ, поэтому в память целиком он не загружается.
- Заголовок `Accept-Encoding: identity` отключает сжатие, чтобы считать реальный объём, а не сжатый.
- Время каждого запроса включает установку соединения (DNS, TCP, TLS): соединения между запросами не переиспользуются. Поэтому результат немного ниже чистой пропускной способности канала.
- Если сервер указал `Content-Length`, а получено меньше байт, запрос считается неудачным.
- Таймаут на операцию сокета: 30 секунд.

## Коды выхода

| Код | Когда |
| --- | --- |
| 0 | все 10 запросов выполнены |
| 1 | ошибка запроса (сеть, HTTP-статус, неполный ответ), измерение остановлено |
| 2 | некорректный URL |
| 130 | прервано пользователем (Ctrl+C) |
